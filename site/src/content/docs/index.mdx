<Section id="code" eyebrow="Code and run" title="Ordinary C#, durable by default" lead="The function from the top of the page, in full. Each step is a call to RunAsync, SleepAsync or another step tool; the rest is plain C#.">

<div class="idn-grid idn-code-trace">
<div>

```csharp title="CheckoutFunction.cs"
using Inngest;

public sealed record OrderPaid(string OrderId, string CustomerId, decimal Amount);

public sealed record Charge(string Id, decimal Amount);

public sealed class CheckoutFunction(IPayments pay, IMailer mail, IWarehouse warehouse)
    : InngestFunction<OrderPaid>
{
    public override async Task<object?> ExecuteAsync(
        FunctionContext<OrderPaid> context, CancellationToken cancellationToken)
    {
        var order = context.Event.Data;

        var charge = await context.Step.RunAsync("charge",
            ct => pay.ChargeAsync(order, ct));

        await context.Step.RunAsync("send-receipt",
            ct => mail.SendReceiptAsync(order, ct));

        await context.Step.SleepAsync("cooling-off",
            TimeSpan.FromMinutes(30));

        await context.Step.RunAsync("ship",
            ct => warehouse.ShipAsync(order, ct));

        return new { charge.Id };
    }
}

public interface IPayments
{
    Task<Charge> ChargeAsync(OrderPaid order, CancellationToken cancellationToken);
}

public interface IMailer
{
    Task SendReceiptAsync(OrderPaid order, CancellationToken cancellationToken);
}

public interface IWarehouse
{
    Task ShipAsync(OrderPaid order, CancellationToken cancellationToken);
}
```

</div>
<div class="idn-annotations">

**`RunAsync("charge", ...)`** is a step. Inngest stores the charge it returns, and later calls get that stored
result instead of charging again. If it throws, Inngest retries this step alone.

**`RunAsync("send-receipt", ...)`** is a step of its own. If the mail server fails, Inngest retries the receipt,
and the charge stays done.

**`SleepAsync("cooling-off", ...)`** ends the call. Inngest calls the function again in 30 minutes. Nothing runs
or waits in your app meanwhile, and deploys in between do not matter.

**`RunAsync("ship", ...)`** runs after the sleep. By then the charge and the receipt come back from Inngest's
store, not from the payment provider or the mail server.

**`return`** gives the run its output. The SDK answers `200` and Inngest marks the run completed.

</div>

### Write workflows

<div class="idn-grid idn-grid-cards">
<div class="idn-card">

#### Steps that run once

A step's result is saved, so a later call gets it back without running the code again.

{/* check: body OrderPlaced; IPaymentGateway payments; OrderPlaced order */}
```csharp
var paymentId = await context.Step.RunAsync(
    "charge", ct => payments.ChargeAsync(
        order.CustomerId, order.Total, ct));
```

[Steps guide](/inngest-dotnet/guides/steps/)

</div>
<div class="idn-card">

#### Sleep and wait for events

Pause for days, or until an event arrives, without holding a thread or a worker.

{/* check: body UserSignedUp */}
```csharp
var activated = await context.Step
    .WaitForEventAsync<UserActivated>(
        "activation", TimeSpan.FromDays(3));
```

[Sleep and wait guide](/inngest-dotnet/guides/sleep-and-wait-for-events/)

</div>
<div class="idn-card">

#### Parallel steps

Start steps together and await them with `Task.WhenAll`; Inngest runs each in its own call.

{/* check: body UserSignedUp; IProfiles profiles; string[] userIds */}
```csharp
await Task.WhenAll(userIds.Select(userId =>
    context.Step.RunAsync($"load-{userId}",
        ct => profiles.LoadAsync(userId, ct))));
```

[Parallel steps guide](/inngest-dotnet/guides/parallel-steps/)

</div>
<div class="idn-card">

#### Fan-out over a list

Run a step for each item of a list, with a limit on how many run at once and the results back in order.

{/* check: body JsonElement; IBilling billing; IReadOnlyList<Invoice> due */}
```csharp
await context.Step.MapAsync("charge", due,
    (i, ct) => billing.ChargeAsync(i.Id, ct),
    new FanOutOptions { MaxParallelism = 5 });
```

[Fan-out guide](/inngest-dotnet/guides/fan-out/)

</div>
<div class="idn-card">

#### Invoke other functions

Run another function as a step and get its typed result back, with its own retries and history.

{/* check: body JsonElement */}
```csharp
var score = await context.Step
    .InvokeAsync<ScoreAccount, AccountScore>(
        "score-acme", new ScoreRequest("acme"));
```

[Invoking functions guide](/inngest-dotnet/guides/invoking-functions/)

</div>
<div class="idn-card">

#### Scoped steps

Run a step in a dependency injection scope of its own, so a `DbContext` carries no state from one step to the next.

{/* check: body OrderPlaced; string id */}
```csharp
await context.Step
    .RunScopedAsync<IInventory>("reserve",
        (inv, ct) => inv.ReserveAsync(id, ct));
```

[Scoped steps guide](/inngest-dotnet/guides/scoped-steps/)

</div>
<div class="idn-card">

#### Event and cron triggers

Start a function from a typed event, a filtered event or a cron schedule, with its options as attributes or in code.

{/* check: attributes */}
```csharp
[EventTrigger<OrderPlaced>(
    If = "event.data.total >= 500")]
[CronTrigger("0 6 * * 1-5", Timezone = "UTC")]
```

[Functions and triggers guide](/inngest-dotnet/guides/functions-and-triggers/)

</div>
<div class="idn-card">

#### Flow control

Concurrency, throttling, rate limits, debounce, batching, priority and singletons are attributes on the function.

{/* check: attributes */}
```csharp
[Throttle(10, "1m")]
[Concurrency(1, Key = "event.data.accountId")]
[Debounce("30s", Key = "event.data.accountId")]
```

[Flow control guide](/inngest-dotnet/guides/flow-control/)

</div>
<div class="idn-card">

#### Errors and retries

Every step retries on its own. Exceptions stop the retries or ask for a delay.

{/* check: body JsonElement */}
```csharp
throw new RetryAfterException(
    "Rate limited.", TimeSpan.FromMinutes(1));
```

[Errors and retries guide](/inngest-dotnet/guides/errors-and-retries/)

</div>
</div>

<div class="idn-card">

#### Workers without an endpoint

#### Durable endpoints <span class="idn-tag">Experimental</span>

Run steps in an ASP.NET Core endpoint, answer the caller directly, and hand the run to Inngest when a step has to wait or fails. Inngest calls it beta, so the API may still change.

{/* check: statements; WebApplication app */}
```csharp
app.UseInngestDurableEndpoints();
app.MapPost("/pay", (IStepTools step) =>
    step.RunAsync("charge", () => "paid"))
```

<Section id="quick-start" eyebrow="Quick start" title="Your first durable function in five minutes" lead="Install the SDK, write a function and register it, start the dev server, and watch a run go step by step on your machine.">

<Steps>

1. Install the SDK from NuGet. `Inngest.AspNetCore` brings in `Inngest`:

   ```bash
   dotnet add package Inngest.AspNetCore
   ```

2. Write the function, a class with one method. Its attributes give it an id and name the event that starts it.
   Each `RunAsync` call is a step: it runs once and Inngest saves its result. `SleepAsync` pauses the run without
   holding a thread:

   ```csharp title="OnboardUser.cs"
   using Inngest;

   public sealed record UserSignedUp(string UserId, string Email);

   [InngestFunction("onboard-user")]
   [EventTrigger("user/signed-up")]
   public sealed class OnboardUser : InngestFunction<UserSignedUp>
   {
       public override async Task<object?> ExecuteAsync(
           FunctionContext<UserSignedUp> context, CancellationToken cancellationToken)
       {
           var user = context.Event.Data;

           await context.Step.RunAsync("send-welcome-email",
               () => Console.WriteLine($"Sending a welcome email to {user.Email}"));

           await context.Step.SleepAsync("wait-a-moment", TimeSpan.FromSeconds(10));

           await context.Step.RunAsync("send-tips",
               () => Console.WriteLine($"Sending tips to {user.Email}"));

           return new { user.UserId };
       }
   }
   ```

3. Register the function and map the endpoint Inngest calls:

   ```csharp title="Program.cs"
   using Inngest;

   var builder = WebApplication.CreateBuilder(args);

   builder.Services
       .AddInngest(options => options.AppId = "shop")
       .AddFunction<OnboardUser>();

   var app = builder.Build();
   app.MapInngest("/api/inngest");
   app.Run();
   ```

4. Set `INNGEST_DEV=1`, which points the SDK at the local dev server, and start the app with
   `dotnet run --urls http://localhost:5280`. Then run the
   [Inngest dev server](https://www.inngest.com/docs/local-development):

   <DevServer />

5. Send a `user/signed-up` event. The dev server takes any event key in the URL. The run appears at
   `http://localhost:8288`, and the app prints the welcome line, then the tips 10 seconds later:

   ```bash wrap
   curl -X POST http://localhost:8288/e/test -d '{"name": "user/signed-up", "data": {"userId": "u1", "email": "ada@example.com"}}'
   ```

</Steps>
