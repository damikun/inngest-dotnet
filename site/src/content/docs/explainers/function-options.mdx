Everything Inngest controls about a function, from its triggers to flow control, goes in `FunctionOptions`. When
Inngest syncs the app, the SDK turns those options into JSON. Pick a preset or change the options, and the output
shows the C# registration and that JSON side by side.

<OptionsBuilder client:visible />

## How the output is made

The builder writes the JSON the same way the SDK's `RegistrationWriter` does: the same properties in the same
order, with durations as Inngest time strings (`90` minutes becomes `"1h30m"`) and options that are not set left
out, so Inngest applies its defaults. A few details worth knowing:

- A function's id on the wire is `<app id>-<function id>`.
- `retries.attempts` holds the number of retries, not attempts. Leave `Retries` empty to get Inngest's default of
  4 retries.
- `Match` on a cancellation becomes the expression `event.<path> == async.<path>`.
- A cron trigger with a time zone is sent with a `TZ=` prefix.
- A class that implements `IFailureHandler` registers a second function, `<id>-failure`, triggered by
  `inngest/function.failed`.

The checks are the ones `FunctionOptionsValidator` makes when the app starts, and the SDK, like the builder, reports
all the problems at once.

## Attributes

The builder writes the options in code. A function class can carry the same options as attributes instead, which
`AddFunction<TFunction>()` reads into `FunctionOptions` when the app starts, so they sync to the same JSON and go
through the same checks. Each attribute sets one member:

| Attribute | Sets |
|---|---|
| `[InngestFunction("id", Name, Retries, Idempotency)]` | `Id`, `Name`, `Retries`, `Idempotency` |
| `[EventTrigger("name", If)]`, `[EventTrigger<T>(If)]` | an `EventTrigger` in `Triggers` |
| `[CronTrigger("schedule", Timezone, Jitter)]` | a `CronTrigger` in `Triggers` |
| `[Concurrency(limit, Key, Scope)]` | a `ConcurrencyLimit` in `Concurrency` |
| `[Throttle(limit, "period", Burst, Key)]` | `Throttle` |
| `[RateLimit(limit, "period", Key)]` | `RateLimit` |
| `[Debounce("period", Key, Timeout)]` | `Debounce` |
| `[BatchEvents(maxSize, "timeout", Key, If)]` | `BatchEvents` |
| `[Priority("run")]` | `Priority` |
| `[Singleton(mode, Key)]` | `Singleton` |
| `[CancelOn("name", If, Match, Timeout)]`, `[CancelOn<T>(If, Match, Timeout)]` | a `CancelOn` in `CancelOn` |
| `[Timeouts(Start, Finish)]` | `Timeouts` |

The trigger, concurrency and cancellation attributes can be repeated. Durations are time strings such as `"30s"`,
`"5m"` or `"1h30m"`. `Middleware` and `Checkpointing` have no attributes; set them with
`AddFunction<TFunction>(options => options with { ... })`, which starts from the attributes. Options passed as
`AddFunction<TFunction>(new FunctionOptions { ... })` replace the attributes.

The site's build checks this page against the SDK: the snippet check compiles the C# of every preset, registers
it in a real app and compares the JSON the SDK sends with the JSON shown here.
